# PRD逆向工程技术要素文档 - 安全机制要素

## 1. MVP身份认证安全架构技术实现

### 1.1 JWT令牌认证机制技术架构
**核心认证策略设计**：
- 令牌算法选择：采用HMAC SHA256对称加密算法，平衡安全性和性能要求
- 配置服务集成：通过NestJS ConfigService实现环境变量驱动的密钥管理
- 令牌生命周期：设置七天有效期作为安全性和用户体验的平衡点
- 签发者标识：固定平台标识符确保令牌来源验证和跨服务识别

**认证流程技术实现**：
- PassportJS策略集成：实现JwtStrategy自动化令牌验证和用户上下文注入
- Bearer令牌传输：标准化Authorization头部承载令牌的HTTP传输方式
- 自动化验证管道：请求级别的令牌有效性检查和用户信息解析
- 会话无状态设计：服务端不维护会话状态，完全依赖JWT令牌承载用户信息

**刷新令牌轮换机制**：
- 双令牌策略：访问令牌短期有效配合刷新令牌长期有效的安全模式
- 令牌轮换算法：使用加密随机数生成器产生32字节十六进制刷新令牌
- 安全存储机制：刷新令牌通过bcrypt哈希后存储，防止数据库泄露风险
- 自动过期清理：数据库级别的刷新令牌过期时间控制和定期清理机制

### 1.2 密码安全处理技术标准  
**密码哈希化技术实现**：
- bcrypt算法应用：采用业界标准的自适应哈希函数，内置盐值生成和验证
- 计算成本配置：使用12轮盐值计算，符合OWASP当前安全建议的时间成本要求
- 环境变量控制：支持通过配置调整盐值轮数，适应不同环境的性能和安全需求
- 密码强度验证：实施最小长度要求和字符复杂度验证，平衡安全性和可用性

**认证安全边界控制**：
- 密码比对机制：使用bcrypt内置的时间恒定比较函数防止时间攻击
- 登录失败处理：统一的认证失败响应，避免用户名枚举和时序分析攻击
- 数据库安全存储：确保明文密码从不进入持久化存储或日志系统
- 密码重置流程：基于令牌的安全密码重置机制，防止未授权密码修改

### 1.3 基于角色的访问控制技术架构
**RBAC权限模型设计**：
- 角色层次结构：建立医师、药房操作员、管理员的三级权限体系
- 单角色分配策略：用户创建时指定唯一角色，简化权限管理复杂度
- 管理员权限继承：超级用户具备全局数据访问和系统配置权限
- 数据边界隔离：非管理员角色严格限制在关联数据范围内的访问权限

**细粒度权限验证机制**：
- Action-Resource权限模型：基于操作动作和资源类型的组合权限定义
- 条件权限验证：支持所有权(OWNERSHIP)和诊所成员(CLINIC_MEMBERSHIP)动态权限条件
- 权限服务架构：PermissionService提供集中化的权限逻辑验证和权限决策
- 多层权限检查：管理员覆盖、细粒度权限、传统角色的三层权限验证体系

**权限拦截和守卫技术**：
- NestJS守卫集成：RolesGuard装饰器实现端点级别的权限保护
- 权限拦截器：PermissionInterceptor实现跨切面的统一权限检查和审计记录
- 数据访问过滤：Service层自动注入用户上下文，实现查询结果的权限过滤
- 异常处理标准化：权限不足时的统一错误响应和日志记录机制

### 1.4 会话管理安全策略
**JWT无状态会话架构**：
- 服务端无状态设计：JWT令牌自包含用户信息，消除服务端会话存储需求
- 多设备并发支持：允许同一用户在多个设备同时登录，提升用户体验
- 客户端登出实现：通过删除客户端令牌实现登出，无需服务端黑名单维护
- 会话超时控制：依赖JWT内置过期时间实现自动会话超时和强制重新认证

**会话安全控制措施**：
- 传输层安全：强制HTTPS传输保护令牌在网络传输中的安全性
- 令牌有效期策略：短期有效期降低令牌泄露的时间窗口风险
- 异常访问检测：通过ApiCallLog表记录IP地址和访问模式，支持异常检测
- 会话信息最小化：JWT负载仅包含必要的用户ID和角色信息，避免敏感数据泄露

## 2. 数据安全保护技术实现

### 2.1 敏感数据分类处理策略
**医疗隐私保护技术边界**：
- 患者数据物理隔离：系统架构层面完全不存储患者个人身份信息
- 处方信息匿名化：处方记录仅包含医疗必需信息，通过QR码实现间接患者关联
- 数据收集最小化原则：严格限制数据收集范围，仅获取业务流程必需的最小数据集
- 用途限制控制：明确定义数据使用目的，防止数据用途范围扩张

**财务数据安全处理**：
- 数值精度保护：使用数据库Decimal类型存储金额，避免浮点数计算精度损失
- 并发访问保护：通过Prisma事务机制和乐观锁策略保护账户余额的并发修改
- 资金流向审计：建立完整的资金变动审计链条，记录每笔交易的来源和去向
- 金额计算验证：实施双重验证机制确保处方总额和履约成本计算的准确性

**个人信息分级保护**：
- 字段级别脱敏：对手机号码等敏感字段实施显示脱敏和日志过滤
- 访问操作审计：记录敏感数据的访问时间、访问用户和操作类型
- 权限最小化实施：严格控制敏感数据访问权限，实现基于角色的数据访问边界
- 数据生命周期管理：建立数据保留期限和安全删除机制

### 2.2 数据传输安全技术保障
**网络传输层安全**：
- HTTPS强制实施：在反向代理层面强制所有HTTP请求升级为HTTPS传输
- TLS协议选择：使用TLS 1.3协议提供前向保密和抗降级攻击保护
- HSTS头部配置：设置HTTP严格传输安全头部，防止中间人攻击和协议降级
- 证书管理策略：采用Let's Encrypt自动化证书管理或商业证书的安全部署

**API数据保护机制**：
- 请求合法性验证：通过JWT令牌验证API请求的身份合法性和权限有效性
- 输入参数清理：使用class-validator装饰器系统实现输入数据的验证和清理
- 响应信息过滤：确保API响应中不包含系统内部敏感信息和调试数据
- 请求响应日志：记录API调用的关键信息，同时过滤敏感数据避免日志泄露

**文件上传安全控制**：
- 文件类型白名单：严格限制上传文件类型为业务必需的特定格式
- 文件大小限制：设置合理的文件大小上限，防止存储空间耗尽攻击
- 文件内容验证：验证文件头部信息确保文件类型真实性，防止恶意文件伪装
- 隔离存储策略：上传文件存储在独立安全目录，与应用代码完全隔离

### 2.3 数据库安全配置技术
**Prisma ORM安全特性**：
- 类型安全查询：利用TypeScript类型系统和Prisma生成的类型定义防止SQL注入
- 参数化查询：所有数据库查询自动使用参数化形式，消除SQL注入风险
- 连接字符串安全：数据库连接信息通过环境变量管理，避免硬编码泄露风险
- 连接池管理：配置合理的数据库连接池大小，防止连接耗尽拒绝服务攻击

**数据访问权限控制**：
- 查询结果过滤：在Service层自动注入用户上下文，确保查询结果符合权限边界
- 数据库事务隔离：选择适当的事务隔离级别，平衡并发性能和数据一致性
- Row Level Security：利用PostgreSQL的行级安全特性实现数据库层面的访问控制
- 备份数据安全：数据库备份文件的加密存储和访问权限严格控制

## 3. 输入验证与恶意攻击防护

### 3.1 API输入验证技术架构
**DTO验证框架集成**：
- class-validator装饰器系统：使用声明式验证装饰器定义输入数据的验证规则
- 全局验证管道：NestJS ValidationPipe全局配置，自动验证所有控制器输入
- 属性白名单控制：启用whitelist和forbidNonWhitelisted选项，拒绝未定义属性
- 类型自动转换：enable transform选项实现输入数据的自动类型转换和清理

**业务字段验证规则**：
- 数值范围验证：处方帖数1-30范围限制，药品重量正数验证，金额非负验证
- 字符长度控制：用户名3-50字符，密码最少8位，文本字段合理长度限制
- 格式验证机制：邮箱格式、电话号码格式、日期格式的标准化验证
- 枚举值验证：角色类型、状态枚举等预定义值的严格验证

**恶意输入防护策略**：
- XSS攻击防护：输入数据HTML实体编码，输出时适当转义，防止脚本注入
- SQL注入防护：Prisma ORM提供的参数化查询和类型安全查询机制
- 路径遍历防护：文件操作严格限制在指定目录范围内，防止目录遍历攻击
- 命令注入防护：避免动态执行用户输入，所有外部命令使用安全的参数化调用

### 3.2 业务逻辑安全验证
**操作权限验证集成**：
- 前置权限检查：每个业务操作执行前验证用户权限和数据归属关系
- 状态依赖验证：验证业务对象当前状态是否允许请求的操作
- 资源访问验证：确保用户只能访问已授权的资源，实现数据访问边界控制
- 跨资源权限验证：涉及多个资源的操作需要验证用户对所有相关资源的权限

**业务规则安全实施**：
- 金额计算双重验证：处方总额和履约成本的独立计算和交叉验证机制
- 状态转换控制：严格控制处方状态、支付状态、履约状态的转换规则和条件
- 并发操作保护：关键业务操作使用数据库事务和乐观锁机制防止并发冲突
- 业务约束强制：通过数据库约束和应用层验证双重确保业务规则的强制执行

**异常情况安全处理**：
- 验证失败标准化：统一的验证失败响应格式，避免内部信息泄露
- 异常状态自动修复：业务异常导致的数据不一致自动检测和修复机制
- 安全审计日志：详细记录业务验证失败和异常操作的完整审计信息
- 降级处理策略：系统异常时的安全降级处理，确保关键功能可用性

### 3.3 文件处理安全控制
**上传文件安全验证**：
- 文件类型白名单：仅允许jpg、jpeg、png等预定义的安全文件格式
- MIME类型验证：验证文件头部的真实MIME类型，防止扩展名伪造攻击
- 文件大小限制：单个文件最大5MB限制，防止存储空间耗尽和上传时间攻击
- 恶意内容扫描：对上传文件进行基础的恶意内容检测和过滤

**文件存储安全策略**：
- 随机文件命名：使用UUID重命名上传文件，避免文件名冲突和路径遍历
- 隔离存储实施：上传文件存储在专用安全目录，与应用代码和配置文件隔离
- 访问权限控制：上传文件通过专用API接口访问，实现细粒度的访问权限控制
- 文件生命周期：建立文件的生命周期管理和定期清理机制

## 4. API安全防护技术实现

### 4.1 请求控制和监控机制
**请求频率限制技术**：
- Throttler模块集成：使用NestJS内置throttler模块实现IP级别的请求频率限制
- 分级限流策略：不同API端点根据业务重要性设置不同的访问频率限制
- 超限处理机制：超过频率限制时返回HTTP 429状态码和用户友好的错误信息
- 动态限流调整：支持基于系统负载和安全威胁动态调整限流参数

**API调用审计系统**：
- 结构化日志记录：ApiCallLog数据库表记录所有API调用的详细结构化信息
- 关键信息捕获：记录请求路径、HTTP方法、用户ID、客户端IP、响应时间、状态码
- 异常模式检测：识别和记录失败请求、异常访问模式和潜在攻击行为
- 性能指标监控：API响应时间、错误率、调用频率等关键性能指标的实时监控

**跨域安全配置**：
- CORS白名单控制：明确配置允许访问的前端域名列表，防止跨域攻击
- HTTP方法限制：仅允许业务必需的HTTP方法(GET、POST、PUT、DELETE)
- 请求头部控制：限制允许的请求头部类型，防止恶意头部注入攻击
- 预检请求处理：正确处理CORS预检请求，确保跨域安全策略的有效实施

### 4.2 错误处理安全机制
**统一异常过滤技术**：
- 错误响应标准化：全局异常过滤器实现统一的错误响应格式和HTTP状态码映射
- 敏感信息保护：确保错误响应中不包含系统内部敏感信息和技术实现细节
- 生产环境保护：生产环境自动隐藏详细错误堆栈信息，防止信息泄露
- 错误分类处理：区分业务异常、系统异常、安全异常的不同处理策略

**安全日志管理策略**：
- 分级日志记录：ERROR级别记录异常详情，INFO级别记录正常业务操作
- 敏感数据过滤：确保日志中不包含密码、令牌、个人信息等敏感数据
- 日志轮转机制：配置日志文件的自动轮转和归档，控制磁盘空间使用
- 日志完整性保护：防止日志文件的恶意修改和删除，确保审计追踪完整性

**调试信息安全控制**：
- 环境差异化：开发环境提供详细错误信息便于调试，生产环境严格过滤
- 错误追踪机制：为每个错误生成唯一追踪ID，便于问题定位和客户支持
- 调试接口保护：开发和调试接口在生产环境自动禁用或严格访问控制
- 系统信息隐藏：避免在错误响应中暴露系统版本、框架信息等技术细节

### 4.3 第三方集成安全控制
**支付接口安全集成**：
- API密钥安全管理：支付服务API密钥通过环境变量安全存储和访问
- 回调签名验证：验证支付服务回调请求的数字签名，确保来源可信性
- 幂等性操作保护：支付操作的幂等性处理机制，防止重复扣款和重放攻击
- 敏感数据保护：支付流程中敏感数据的安全传输和最小化存储

**邮件服务安全配置**：
- SMTP认证机制：邮件发送使用安全的SMTP认证，防止邮件服务滥用
- 邮件内容安全：确保邮件内容不包含恶意脚本、链接或可执行附件
- 发送频率控制：控制邮件发送频率，防止被标记为垃圾邮件或触发反垃圾邮件机制
- 邮件模板安全：使用预定义安全邮件模板，防止邮件内容注入攻击

**外部API调用安全**：
- 网络超时控制：设置合理的外部API调用超时时间，防止服务阻塞
- 重试机制实施：智能重试机制处理临时网络问题，避免业务中断
- 错误处理策略：外部API调用失败的优雅降级处理，确保系统稳定性
- 服务依赖管理：外部服务依赖的健康检查和故障隔离机制

## 5. 安全监控与审计技术架构

### 5.1 实时安全监控系统
**API访问监控技术**：
- 实时访问跟踪：通过ApiCallLog表和内存缓存实现API访问状况的实时监控
- 异常行为检测：基于访问频率、失败率、响应时间等指标的异常访问模式识别
- 自动告警机制：重要安全事件触发邮件、短信或webhook形式的即时告警通知
- 监控数据可视化：API访问趋势、错误率分布、用户活动模式的图表化展示

**用户行为安全监控**：
- 登录活动跟踪：记录用户登录时间、来源IP地址、设备信息和登录结果
- 业务操作审计：详细记录关键业务操作的执行用户、时间戳和操作内容
- 权限变更监控：用户角色变更、权限调整的完整记录和变更历史追踪
- 异常行为识别：识别异常登录地点、异常操作时间、异常权限使用等可疑行为

**系统安全状态监控**：
- 服务健康检查：数据库连接状态、外部服务依赖、关键业务流程的健康状态检查
- 性能安全监控：API响应时间、系统负载、错误率等性能指标的安全阈值监控
- 资源使用监控：CPU、内存、磁盘、网络等系统资源的使用情况和异常检测
- 安全配置监控：关键安全配置的变更检测和合规性验证

### 5.2 审计日志管理体系
**操作审计记录机制**：
- 用户操作完整记录：用户的所有业务操作详细记录，包括创建处方、支付、履约等
- 管理操作审计：管理员的审核决策、配置变更、用户管理等管理操作的完整记录
- 系统操作追踪：自动化处理流程、定时任务、系统维护操作的详细日志记录
- 跨系统操作关联：涉及多个系统或服务的操作的关联记录和追踪

**审计数据完整性保障**：
- 精确时间戳记录：所有审计记录包含高精度时间戳信息，支持时序分析

- 操作结果记录：记录操作的执行结果、影响范围和相关数据变更

**审计数据安全保护**：
- 只写访问模式：审计日志采用只写设计，防止历史记录的恶意篡改
- 访问权限严控：审计日志仅限管理员访问，实施严格的查看和导出权限控制

### 5.3 安全事件响应机制
**安全事件分类体系**：
- 高危事件识别：未授权访问尝试、数据泄露风险、系统入侵迹象的自动识别

- 即时响应措施：高频异常访问自动触发临时IP地址封禁和访问限制

- 证据保存机制：安全事件相关的日志、状态、配置信息的自动保存和固化

**恢复和加固策略**：
- 数据恢复机制：关键业务数据的快速备份恢复和业务连续性保障
- 服务恢复流程：系统服务中断后的快速恢复流程和服务可用性恢复
- 安全加固措施：安全事件后的系统安全配置加固和漏洞修复措施
- 事后分析改进：安全事件的根因分析、经验总结和预防措施改进
