# PRD逆向工程技术要素文档 - 集成交互要素

## 1. MVP服务集成架构设计技术实现

### 1.1 NestJS依赖注入集成技术框架
**核心依赖注入容器技术架构**：
- @Injectable装饰器实现服务类的自动注册和生命周期管理
- Constructor注入模式确保服务依赖的类型安全和编译时检查
- @Inject装饰器实现配置服务和第三方服务的动态注入
- 单例模式确保数据库连接池和缓存服务的全局状态一致性

**模块化服务集成技术策略**：
- @Module装饰器实现providers、controllers、imports的模块化组织
- forRoot/forRootAsync模式实现配置驱动的模块初始化和环境变量集成
- 跨模块服务依赖通过exports暴露和imports导入实现松耦合
- ConfigService统一管理环境配置、数据库连接、第三方API密钥

**服务生命周期技术管理**：
- OnModuleInit钩子实现服务初始化、资源准备和健康检查
- OnModuleDestroy钩子实现资源清理、连接关闭和优雅停机
- DEFAULT作用域单例模式确保服务状态一致性和性能优化
- REQUEST作用域请求级依赖注入用于特殊业务场景

### 1.2 事件驱动集成技术机制
**EventEmitter2事件系统技术实现**：
- @OnEvent装饰器实现编译时事件订阅和类型安全事件处理
- 强类型事件接口定义确保事件负载结构的一致性和验证
- 同步事件发布机制确保业务操作与事件通知的原子性
- 错误隔离机制确保单个事件处理器失败不影响其他处理器

**核心业务事件技术定义**：
- PaymentSucceeded/PaymentFailed事件触发处方状态更新和账户余额调整
- FulfillmentCompleted事件触发PO生成和药房账户余额更新
- PurchaseOrderApproved/PurchaseOrderRejected事件控制资金流转
- WithdrawalRequested事件触发Invoice生成和邮件发送

**事件可靠性技术保障**：
- 事务一致性：事件发布与数据库操作在同一Prisma事务中执行
- 基础重试机制：事件处理失败时的自动重试和异常处理
- 事件日志记录：EventLog表记录事件处理状态和失败信息
- 幂等性保护：事件处理器实现幂等性逻辑防止重复处理

## 3. API集成交互技术标准

### 3.1 RESTful API设计技术规范
**HTTP方法语义技术标准**：
- GET用于数据查询和资源获取，支持幂等性操作
- POST用于资源创建和非幂等操作，支持幂等性键
- PUT用于资源完整更新，支持幂等性操作
- PATCH用于资源部分更新，支持条件更新
- DELETE用于资源删除，支持软删除和级联删除

**资源路径设计技术规范**：
- /api/v1/{resources}统一资源路径结构
- 嵌套资源关系：/prescriptions/{id}/medicines表达资源层次
- 查询参数过滤：?status=active&page=1支持数据过滤和分页
- 路径参数验证：{id}参数的格式验证和存在性检查

**响应格式技术标准化**：
- ApiResponseV12Dto统一响应信封格式
- success字段明确操作结果状态
- data字段承载业务数据和泛型类型支持
- error对象包含code、message、details结构化错误信息

### 3.2 API版本控制技术策略
**URI版本控制技术实现**：
- /api/v1前缀版本控制和NestJS VersioningType.URI配置
- 版本路由自动解析和端点版本映射
- 默认版本设置避免无版本请求的处理歧义
- 版本弃用通过Sunset头部提供迁移指导

**API文档版本管理技术流程**：
- docs/api/UNIFIED_API_DOCUMENTATION_v1.md唯一权威文档
- docs/api/API_CHANGELOG_v1.md记录变更历史和时间线
- 版本升级时新文档替代和旧版本归档
- Swagger自动生成和文档同步机制

**向后兼容技术保证**：
- 非破坏性变更不增加版本号确保客户端无缝升级
- 破坏性变更新版本并行提供和渐进式迁移
- Accept头部Version字段实现临时版本覆盖
- API使用统计和版本迁移监控

### 3.3 API安全集成技术机制
**JWT认证集成技术实现**：
- PassportJS策略集成和Bearer Token标准传输
- JwtStrategy自动令牌验证和用户上下文注入
- 令牌生命周期管理：7天有效期和刷新令牌轮换
- 认证异常处理：401/403状态码和错误信息标准化

**RBAC权限集成技术架构**：
- @AuthRoles装饰器实现端点级权限控制
- PermissionService集中权限逻辑验证和决策
- 数据访问边界：医师仅访问自有数据，药房仅处理分配订单
- 管理员权限继承和全局数据访问能力

**API调用监控技术实现**：
- ApiCallLog表记录所有API调用详细信息
- 性能监控：响应时间、错误率、调用频率统计

## 4. 数据交换集成技术架构

### 4.1 DTO数据传输技术标准
**class-validator验证集成技术实现**：
- 装饰器驱动验证：@IsNotEmpty、@IsString、@IsNumber等类型验证
- 业务规则验证：@Min、@Max、@IsEnum枚举值和范围验证
- 嵌套对象验证：@ValidateNested、@Type深层对象验证和转换
- 自定义验证器：复杂业务逻辑验证和条件验证

**ValidationPipe全局配置技术参数**：
- whitelist:true自动移除未定义属性防止参数污染
- forbidNonWhitelisted:true主动拒绝非白名单属性请求
- transform:true实现类型自动转换和数据清理
- transformOptions.enableImplicitConversion支持深层类型推断

**错误响应技术标准化**：
- 字段级错误定位通过property和constraints精确定位
- 多字段验证错误聚合到errors数组批量返回
- 国际化错误消息通过Accept-Language和错误码映射
- 验证失败统一响应格式和用户友好错误描述

### 4.2 数据序列化技术机制
**class-transformer集成技术实现**：

- classToPlain转换确保循环引用安全和序列化性能
- 深度限制控制避免无限递归和堆栈溢出

**JSON数据处理技术优化**：
- 时间戳标准化：toISOString()生成UTC时间确保跨时区一致性
- 数值精度处理：Decimal类型序列化和浮点数精度保护
- 枚举值映射：数据库枚举到API响应的映射和转换
- 分页元数据：total、page、limit、totalPages标准化分页信息

### 4.3 数据库集成技术优化
**Prisma Client集成技术特性**：
- 类型安全查询和编译时类型检查防止运行时错误
