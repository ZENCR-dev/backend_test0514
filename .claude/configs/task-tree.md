# 四层任务树管理规范

## 层级结构

### 1. PRPs（项目级基石文档）
- **位置**：`.claude/prps/`
- **功能**：项目级重要文档，长期维护
- **示例**：架构设计、技术选型、商业模式
- **更新频率**：低频，重大决策时更新

### 2. Checklist（阶段级任务清单）
- **位置**：项目根目录
- **功能**：阶段性开发任务清单
- **示例**：`MVP2.5-CHECKLIST.md`
- **更新频率**：中频，每个开发阶段更新

### 3. 进度日志（记录级高频日志）
- **位置**：项目根目录
- **功能**：开发进度记录，问题追踪
- **示例**：`PROGRESS_LOG.md`
- **更新频率**：高频，每日或每次开发更新

### 4. Todos（临时级任务）
- **位置**：Claude Code CLI内置
- **功能**：短期任务管理，实时跟踪
- **工具**：TodoWrite CLI工具
- **更新频率**：极高频，实时更新

## 任务树路径追踪

### 路径格式
```
项目级(PRP) > 阶段级(Checklist) > 记录级(Progress) > 临时级(Todo)
```

### 当前项目四层任务树定义

#### 第1层：PRP（项目级基石文档）
**指定文档**：`docs/PRDSOPMVP2.0.md`
- 作为项目级需求和业务流程基石
- 定义新西兰中医药电子处方平台的完整商业模式
- 包含B2B2C差价盈利模式和完整业务流程

#### 第2层：Checklist（阶段级基石文档）
**指定文档**：`docs/MVP2.5-DEVELOPMENT-PLAN.md`
- 作为当前阶段的开发计划基石
- 基于docs/MVP2.5.md的功能需求进行具体实施规划
- 包含Phase 3.2财务操作增强的详细任务分解

#### 第3层：Progress Log（记录级高频日志）
**指定文档**：`MVP2.5-PROGRESS-LOG.md`
- 整合现有的progress_tracker_mvp2.0.md内容
- 记录每日开发进展和问题解决
- 跟踪任务完成状态和技术债务

#### 第4层：Todos（临时级任务）
**工具**：Claude Code CLI TodoWrite
- 实时管理当前具体执行任务
- 从Checklist中拆分出的具体实施步骤
- 动态更新任务状态和优先级

### 当前任务树路径示例
```
PRDSOPMVP2.0 > Phase 3.2财务操作增强 > Day15-批量API开发进展 > 实现批量PO审批接口
```

## 使用规则

### AI任务管理
- 每次开发前检查TodoWrite状态
- 优先处理高优先级任务
- 完成后立即标记为completed
- 使用路径追踪避免任务迷失

### 任务回溯机制
- 完成最底层Todos后自动回溯到上级
- 支持跨层级任务跳转
- 保持任务树状态持久化

### 文档同步
- 任务完成后同步更新对应层级文档
- 关键决策同步到PRP层级
- 问题和解决方案记录到进度日志
